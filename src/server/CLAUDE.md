# CLAUDE.md (server)

## PublisherServer request flow

`src/server/publisher-server/index.ts`:

1. Select the collection. This is the `collectionName` option of `serveRequest()`/`serveFallback()`, or else the active collection: the default collection, or the collection from `setActiveCollectionName`. The helpers are in `collection-selector/` (for example host, cookie, config store).
   The state of a request is in a `CollectionScope`: the settings, the index, and the `Server-Timing` collector (`util/server-timing.ts`, on only if `setServerTimingRequestHeader()` names a header that the request has). The scopes are in a `WeakMap`, keyed by the `Request` and then the collection. Thus a reused sandbox does not keep the state of a previous request, and two calls for one request read the index one time. The methods that take no request (`getMatchingAsset()`, `serveAsset()`, …) use the current scope, which `beginRequest()`, `serveRequest()`, and `setActiveCollectionName()` replace. The old public fields `serverTiming`, `settingsCached`, and `assetEntryMapCache` are read-only `@deprecated` getters over the current scope. Remove them in v9.
2. If `setResponseCache()` is set, `serveCached()` (`response-cache.ts`) looks up the whole response in the Core Cache, keyed by publish ID, collection, path, and normalized `Accept-Encoding`. The path part is `<path>|no-html` when there is no fallback page (`fallback: false`, or a client that does not accept HTML), and `|fallback` for `serveFallback()` (a real path always starts with `/`, so `serveRequest()` throws for a `pathname` option without it). A hit skips steps 3 to 8. A miss uses `transactionLookup()`, so concurrent misses wait for one fill. The fill runs steps 3 to 8 with a `GET` that has no conditional headers, and caches a `200`, a `404`, or "not found". Conditional requests and `HEAD` are then answered from the cached response. The fill reads the whole body (`readBodyUpTo()`) before `insert()`, and calls `cancel()` if the read fails. A body larger than `maxBodySize` gets a "too large" marker entry, and is served from storage. Do not stream into the entry with `insertAndStreamBack()`: on a real service, a fill that is short, abandoned, or not closed is not stored, but the filler and the waiters still get a short body that ends as if complete. Viceroy is different again: it stores such a fill.
   `serveAsset()` passes the stored body through `checkBodyLength()` (`util/body-length.ts`), which compares it with the variant's `size`. An empty body throws before the response starts. Any other mismatch stops the stream with an error, which resets the response on a real service.
3. Load the settings and the index for that collection, and keep them in the scope. An expired collection is the same as a collection that does not exist.
4. to 8. Find the file, select the encoding, process the conditional headers, and set the cache headers (see the code).
